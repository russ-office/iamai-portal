01

Что такое Лаборатория

Лаборатория — вы своими руками превращаете рабочие задачи, которые съедают время, в готовые решения. Цепочка: проблема → решение → техническое задание (ТЗ). Идём спринтами по 2 недели. Результат измеряем в сэкономленных часах.

02

Этапы пути задачи (T0–T7)

Задача проходит этапы — от проблемы до готового ТЗ. Каждый этап = форма (не «свободный чат»); следующий открывается, когда предыдущий квалифицирован. Сумма кусков превращает проблему в ТЗ.

T0/T1 Бэклог
T2 Решение
T3 Поиск
T5 Прототип
T6 Тест
T7 PRD / ТЗ
T0/T1 · Бэклогописание проблемы + оценка времени (цена проблемы)
T2 · Решениеполная триада: проблема · вход · выход (= будущие критерии)
T3 · Поисканалоги рынка + verdict (подходит/нет) → общий каталог
T5 · ПрототипJTBD + мини-PRD: подход · стеки · критерии тестирования
T6 · Тестплан тестов + протокол «до/после» против критериев триады
T7 · PRD / ТЗготовое ТЗ + факт экономии (сэкономленные часы)
Бэклог → Решение → Поиск ─┬─ аналог подошёл ──────────▶ Тест ── прошло ──▶ PRD / ТЗ └─ не нашлось ── Прототип ──▶ Тест ── не прошло ──▶ Прототип (петля)
Shortcut T3→T6нашли готовый аналог, подходит по триаде → не строим свой прототип, сразу тест. Цель Лаборатории — экономия времени, а не «обязательно с нуля».
Петля T6→T5тест не прошёл → назад в Прототип, дорабатываем. Несколько кругов — нормально.
03

Триада: как описать решение

На этапе «Решение» (T2) описываешь триадой:

1 Вход
что есть сейчас — сырьё, состояние.
2 Выход
что станет — результат.
3 Критерии приёмки
проверимое условие «сделано».
До · размыто
«отчёт хороший»
После · проверимо
«отчёт собирается <5 мин из 3 источников без правок»

Критерии фиксируются на входе в Прототип и не переписываются после сборки — протокол «до-после» меряет против них.
